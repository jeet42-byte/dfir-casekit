## 1. Executive summary

On 18 November 2026 a finance user on **WS-FIN-07** opened a macro-enabled attachment
(`Invoice_Nov2026.docm`) delivered by email. The macro ran an encoded PowerShell download
cradle that fetched a second stage over HTTP and installed an implant masquerading as
`svchost.exe` in `C:\Users\Public\Libraries`, persisted through a `Run` key, and beaconed to
`api.cdn-sync[.]example` every ~60 seconds.

About 25 minutes later the operator dumped LSASS memory with `comsvcs.dll MiniDump`. The
domain-admin credentials of **adm.rahman** were exposed because that account had logged on
interactively (RDP) to the workstation for helpdesk work at 07:52. At 09:31 the attacker used
the account's NTLM hash to authenticate to **DC01** (pass-the-hash), executed commands through
PsExec, and created a backdoor domain admin, **svc_backup**.

Finance data from `\\FS01\Finance\Q3-2026` was compressed into a password-protected archive and
~1.6 MB was sent over TLS to `203.0.113[.]50`; a second, DNS-tunnelled channel to
`tlmcache[.]example` carried a further ~1.4 KB (2.2 KB base32-encoded) - consistent with a
credential-dump extract or key material. The attacker deleted the
workstation's shadow copies and cleared the DC01 Security log. DC01 events were recovered from
the Windows Event Forwarding collector, which retained them after the local clear.

An unrelated, unsuccessful SSH password-guessing run against internet-facing **WEB01** from
`198.51.100[.]23` was also observed; it is assessed as opportunistic background noise.

**Assessment:** full domain compromise with confirmed data exfiltration. Severity: Critical.

**At a glance:** 24 findings (1 critical, 17 high, 6 medium) across 3 host(s): DC01, WEB01, WS-FIN-07. 25 distinct MITRE ATT&CK techniques. Malicious activity spans 2026-11-18 07:40:04 → 2026-11-18 10:29:34 UTC.

## 7. Detailed findings

### 7.1 🟥 LSASS memory dump via comsvcs.dll MiniDump or procdump

**Severity:** Critical · **Detector:** sigma (`ck-win-005`) · **Hosts:** WS-FIN-07 · **Events:** 2

**ATT&CK:** [T1003.001 OS Credential Dumping: LSASS Memory](https://attack.mitre.org/techniques/T1003/001/), [T1218.011 System Binary Proxy Execution: Rundll32](https://attack.mitre.org/techniques/T1218/011/)

rundll32 invoked comsvcs.dll's MiniDump export (or procdump targeted lsass). This writes the
memory of LSASS - which holds NTLM hashes and Kerberos tickets of logged-on users - to disk
for offline credential extraction with Mimikatz/pypykatz.

**Evidence:**

- Block cdn-sync[.]example, tlmcache[.]example, 203.0.113[.]45 and 203.0.113[.]50 at DNS, proxy and firewall; sweep the estate for the implant hash and the OneDriveSync Run value.
- Stop domain admins logging on to workstations: use a tiered admin model, Privileged Access Workstations and the Protected Users group.
- Remove local administrator rights from standard users; block Office macros from internet-sourced files by Group Policy.
- Engage legal/DPO: Q3 finance data was exfiltrated - assess notification obligations.

**Technique-specific controls**

- **T1003.001 OS Credential Dumping: LSASS Memory:** Treat every credential used on the host as compromised: reset passwords, reset krbtgt twice, enable LSA Protection (RunAsPPL) and Credential Guard.
- **T1021.002 Remote Services: SMB/Windows Admin Shares:** Block workstation-to-workstation/server SMB (445) at the host firewall except from admin jump hosts.
- **T1041 Exfiltration Over C2 Channel:** Block the destination IP at the perimeter; quantify the data exposed and assess notification duties.
- **T1048 Exfiltration Over Alternative Protocol:** Block the tunnelling domain; alert on long, high-entropy DNS labels and per-host DNS volume.
- **T1059.001 Command and Scripting Interpreter: PowerShell:** Enable PowerShell Script Block Logging (EID 4104) and Constrained Language Mode; alert on -EncodedCommand.
- **T1070.001 Indicator Removal: Clear Windows Event Logs:** Forward logs to a SIEM in real time so local clearing cannot destroy evidence; alert on EID 1102/104.
- **T1071.004 Application Layer Protocol: DNS:** Sinkhole/block the C2 domain at DNS; force all DNS through internal resolvers and monitor query entropy.
- **T1098 Account Manipulation:** Audit privileged group membership (Domain Admins, Administrators) and alert on EID 4728/4732/4756.
- **T1105 Ingress Tool Transfer:** Block the staging URL/domain at the web proxy; restrict PowerShell's outbound web access.
- **T1110.001 Brute Force: Password Guessing:** Rate-limit and lock out after repeated failures; enforce MFA; remove internet exposure of SSH/RDP where possible.
- **T1136.002 Create Account: Domain Account:** Disable and remove the rogue account; review all accounts created during the intrusion window.
- **T1204.002 User Execution: Malicious File:** Disable macros from the internet via Group Policy (Block macros in Office files from the Internet).
- **T1490 Inhibit System Recovery:** Protect backups offline/immutable; alert on vssadmin/wmic shadowcopy deletion.
- **T1547.001 Boot or Logon Autostart: Registry Run Keys:** Remove the Run-key value and the dropped binary; hunt the same value name across the estate.
- **T1550.002 Use Alternate Authentication Material: Pass the Hash:** Reset the affected privileged account; restrict NTLM, add admins to Protected Users, deploy LAPS for local admin passwords.
- **T1560.001 Archive Collected Data: Archive via Utility:** Alert on archivers (7z, rar, makecab) writing to staging directories on workstations.
- **T1566.001 Phishing: Spearphishing Attachment:** Block the sender and attachment hash at the mail gateway; purge the message from all mailboxes.
- **T1569.002 System Services: Service Execution:** Alert on EID 7045 service installs on servers; remove PsExec-style services (PSEXESVC).

## 10. Conclusion

The intrusion progressed from a single opened attachment to domain-admin control in under an
hour. Two control gaps made that speed possible: a privileged account's credentials resident on
a standard workstation, and a standard user with local administrator rights (needed to read
LSASS). Centralised log forwarding preserved the evidence the attacker tried to destroy, and is
the reason this reconstruction is complete.

## Appendix B — Methodology and limitations

- Evidence was hashed (MD5/SHA-1/SHA-256) on intake, set read-only, and re-verified when this report was produced.
- Windows logs were matched against Sigma rules (`rules/`); cross-event behaviour (brute force, beaconing, DNS tunnelling, bulk transfer) was detected by threshold analytics whose numbers are stated in each finding.
- PCAP analysis is per-packet with no TCP reassembly; payloads split across segments are not inspected. Encrypted content was not decrypted — TLS findings rely on SNI and flow metadata.
- Absence of a detection is not evidence of absence: coverage is limited to the log sources supplied.
